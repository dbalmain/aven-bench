# Results — diagnostic format A/B (`diagfmt-01`)

Pre-registration: `analysis/prereg-diagfmt-01.md` (committed `e99d0f7`, before
the first attempt; retry policy amended `ad3fefa`, before any analysis was run).
Report generated by `analysis/diagfmt-ab.ts` (committed `6fea62e`, before any
rows existed).

Runs: `phase4-diagfmt-text-01`, `phase4-diagfmt-agent-01`. 213 attempts per arm,
71 holdout tasks × 3 samples, aven-lang `8ca8620`, doc v2 `dfa665f6`,
`opencode-go/deepseek-v4-flash`, rounds ≤ 3, `no-verify`, hidden suite,
bubblewrap.

## Headline

**Null, and a precise one.** Rendering Aven's diagnostics in `--format agent`
instead of the default ariadne style did not change how many repair rounds the
model needed.

|                           | text  | agent |
| ------------------------- | ----- | ----- |
| usable attempts           | 209   | 212   |
| excluded `harness_error`  | 4     | 1     |
| excluded contaminated     | 0     | 0     |
| mean DV (censored rounds) | 1.100 | 1.099 |
| eventually green          | 86.6% | 84.9% |
| first-shot                | 49.8% | 52.4% |

Primary, as pre-registered — paired Wilcoxon on 71 per-task mean DVs:

```
mean(DV_text − DV_agent)   0.019 rounds     (positive ⇒ agent needs fewer)
Wilcoxon n (non-zero) 44   27 zero-diff pairs dropped
W+ 481.0   W− 509.0   z 0.158   p 0.874
```

**VERDICT: NOT SIGNIFICANT.** Nowhere near the pre-registered 0.3-round bar.

### The negative control passed, which is what makes the null trustworthy

`firstShotPass` 49.8% (text) vs 52.4% (agent), z = −0.533, p = 0.594. Round-0
prompts were byte-identical by construction and the data agree. Had this
differed, the primary would have been uninterpretable.

## Post-hoc precision — NOT pre-registered, reported as descriptive

A null is only worth anything if the study could have seen the effect it was
looking for. It could:

```
paired n = 71   mean diff 0.019   sd 0.679   se 0.081
95% CI  [−0.142, +0.179] rounds     pre-registered bar: 0.30
minimum detectable effect (80% power, α=.05): ~0.226 rounds
```

The confidence interval excludes ±0.3 in **both** directions, and the MDE sits
below the bar. This is an informative null, not an underpowered one.

## The caveat that matters more than the headline

**The IV only fired on about a third of attempts.**

|                                           | text             | agent            |
| ----------------------------------------- | ---------------- | ---------------- |
| attempts ever shown a compiler diagnostic | 79 / 209 (37.8%) | 64 / 212 (30.2%) |
| diagnostic-bearing repair prompts         | 120              | 97               |

The pre-registered primary is an **intent-to-treat** estimate over the whole
holdout, and as such it is correct and precise: switching the harness default to
`--format agent` would not move the corpus. But roughly two thirds of attempts
either passed first shot or failed in a way that never quoted a compiler
diagnostic, so they contribute a guaranteed zero difference and dilute the
estimate.

Scaling the ITT interval by the ~1/3 exposure rate puts the plausible
**per-exposure** effect at roughly ±0.5 rounds. **A meaningful effect among
attempts that actually see a diagnostic is not ruled out by this experiment.**

The pre-registered secondary stratum was the right instrument for that question
and turned out badly underpowered: only 16 of 71 tasks had ≥2 samples with a
round-0 `check` failure in both arms (25 dropped for short samples). It reported
mean −0.094 rounds, p = 0.528 — null, but on n = 13 non-zero pairs, which
establishes nothing either way.

Anyone re-running this should power on the **exposed** subset, not the corpus:
select tasks that reliably fail `check` at round 0, and buy more samples of
those rather than more tasks.

## What this says about where to spend effort

Diagnostic **form** is not the bottleneck for this model on this corpus. That is
a real result and it redirects attention to diagnostic **content** — whether the
message names the right fault and the right repair — which this experiment held
constant by design and did not test.

Task #33 is a concrete instance found incidentally while validating the harness
for this very run: `f = (a: Text) => a.slice(1, 2, 3)` reports the correct arity
under a label and note belonging to an entirely different fault, telling the
reader to edit the lambda's parameters when the repair is to drop a call
argument. No rendering fixes that.

## Scope

One model, one corpus, one skill doc, n = 3, Aven only. The absolute rates here
are **not** comparable to holdout-05/-06: the skill doc is one commit newer.
Both arms share every one of those factors, so the comparison between them
stands on its own.
